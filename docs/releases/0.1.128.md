# 0.1.128 项目审计加固

根据全项目代码审计修复安全、发布与运行稳定性问题。安装入口经用户明确授权修改；公开安装 URL、外层命令、单进程安装方式和 macOS quarantine 清理保持原样。

## 主要变更

- 备份导入与导出只允许设置页可编辑的配置项；平台地址、更新地址、本机路径和代理凭据不再随备份迁移，堵住导入备份改写平台地址、把设备令牌发往第三方的入口。
- 首页看板的赛道定位文本转义后再渲染，修复存储型 XSS。
- 自动化批次中单篇发布在重试耗尽后保留通过稿并继续下一篇；仅在账号掉线或自动化关闭时停止后续稿件。
- 原创声明与 AI 声明按用户选择精确开启或关闭，并在唯一一次发布点击前再次核验；自动化不再强制开启 AI 声明。
- 本机密钥改为每台安装随机生成的独立密钥，旧密文在首次成功读取时自动升级。
- Windows 打开本机页面不再经过 cmd.exe，避免 URL 中的 & 截断口令。
- 平台登录授权按代次绑定，旧轮询不能在登出或重新登录后写入令牌。
- 接通 CLI 批量取消信号；后台任务清理异常隔离；清理生成队列遗留锁文件；采用平台下发的排队等待时长；非 ASCII 错误口令返回 403。
- 桌面 smoke 必须显式提供隔离数据目录，两个平台的冻结包 smoke 均已传入。
- 安装器停止旧客户端时等待退出，超时强制结束后仍无法确认退出则中止安装；按通道精确停止渲染器；macOS PATH 提示改用调用前路径。
- 移除未调用的客户端内整包替换与 skill 下载代码。

## 构建与回归

- macOS：1377 项通过。
- Windows：1374 项通过，3 项平台相关测试跳过。
- 首轮 Windows 构建因一个新增测试未指定 UTF-8 读取而失败，产品代码不受影响；修复后在 GB18030 区域设置下本机全量回归通过，第二轮双平台构建通过。
- 两个平台的冻结包 smoke（各 22 项断言）与安装事务 smoke 通过，覆盖正式/测试共存、重复安装、升级、数据库副本升级验证、卸载隔离。
- 两端 hostile smoke 观测到的四个安装入口摘要与已提交字节一致，无二段 shell、无安装 helper 请求。

发布 Skill 的 RedBeacon 入口信任锚中四个安装入口摘要已更新为本版本字节，四个卸载入口不变。修改前原文件备份在本机 dist/trust-anchor-backups/before-0.1.128-20260919/。

## 已知风险

- 外版 RedNote 发布页未验证是否具备原创声明与内容类型声明控件；本版本对每篇图文都会核验这两个控件，缺失时该笔记发布失败。
- 导入备份后代理配置被清空，需要重新配置。
- “从正式版同步测试数据”后，测试通道无法读取正式通道加密的代理配置，需要重新配置。
