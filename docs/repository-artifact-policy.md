# 仓库文档与生成产物保留规则

## 发布回执：每通道最多三个完整版本

`docs/download-node/releases/<channel>/` 是发布回执目录。保留窗口按 **版本** 计数，同一版本的重试回执作为一组处理，stable 与 test 分开计算。保留最近三个完整版本，并始终包含 canonical 当前指向的版本；canonical 较旧时，它占用三个名额之一。一次中止的发布不算完整版本，不占成功版本名额。

权威保留集来自全局发布 Skill 同一 run 的版本保留检查结果。项目盘点工具只提出本地回执计划，不代替 OSS 对象核验，不处理 OSS、本机发布运行目录或下载节点的清理权限。失败、未完成、绑定异常的回执和未提交的文件必须人工单列，不能自动删除。

每次发布收尾时：

1. 从当次 `publication-result.json` 或两份小型 canonical 清单确认 stable/test 当前版本；不能用本地源码版本推断。
2. 运行 `python tools/plan_release_receipts.py --canonical-version stable=<正式当前版本> --canonical-version test=<测试当前版本>`。命令只读取该回执目录与 Git 文件清单，输出保留版本、超窗且已跟踪的完整回执、需人工处理的记录；没有删除、移动、上传或网络功能。
3. 将计划与全局发布 Skill 实际保留集核对。超窗回执退出当前 Git 工作树时，应在专门的维护提交中审阅；旧提交继续保留原始证据，不重写 Git 历史。用户尚未提交的文件保持原样。
4. 新回执与窗口调整一起审阅，避免持续只增不减。独立问题分析、架构文档、发布契约和接入文档不受此产物窗口影响。

## 工作台 skill：保留入库，禁止独立维护

继续跟踪 `.agents/skills/source-command-redbeacon*/SKILL.md`。它们有明确的首次使用价值：用户在新机器 clone 公开仓库后，Codex 可以直接发现项目能力，无须先取得私有 `cli/` 或运行生成器。当前只有 16 份，保留这份派生副本的成本可控。

唯一正文真源仍是 `.claude/commands/redbeacon*.md`。工作台同步先渲染 stable 占位符，再使用公开 `build_channel_skills.py` 的 `portable_skill_text`；只改工作台名称和斜杠入口引用，发布包的转换逻辑保持共享。

- 修改真源后运行 `python tools/sync-codex-skills.py --workspace-only`，同时提交真源和派生差异。该模式不加载私有 CLI，也不写用户已安装的 skill。
- `python tools/sync-codex-skills.py --check` 只读比较 UTF-8 字节与完整文件集合，任何缺失、手改或多余副本都会失败。公开 CI 强制运行此检查。
- 不对派生正文打补丁，不给不同 AI 宿主维护第二份正文。普通构建输出仍放入已忽略的 `dist/` / `build/`。

校验器测试还会构造没有 `cli/` 的临时公开仓库，验证生成及只读检查可独立运行，并验证检查失败时不会替用户改回文件。
