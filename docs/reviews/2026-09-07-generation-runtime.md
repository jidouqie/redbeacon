# 生成运行时与后台任务持久化评估

任务 12 把生成顺序、账号自动化占用和生成任务状态放到当前业务数据库同目录的 `generation.sqlite3`。运行记录与业务库分开：备份恢复不会把旧机器的活跃执行权带到新机器。业务账号和已保存稿件仍以 `redbeacon.db` 为准。

## 已实现的生成行为

- UI 在返回任务编号前取得 SQLite 顺序号，本机回调入队与取得顺序号在同一临界区；CLI 无法插到已排队的 UI 稿件前面。
- 普通图文、带货、预生成、继续出图、自动化批次使用同一个跨进程工位，最多等待 20 项。平台算力调度器继续负责账号级 AI 并发和重试。
- 宿主创作的准备、平台兜底与提交命令也经过该工位；两次命令之间由原有 `creation_topic_reservation` 保留选题，外部宿主 AI 的执行时间不占住一个已退出 CLI 的进程锁。被宿主预留的选题不会进入自动挑题列表，指定该选题走另一生成路径会在收费前拒绝。
- 自动化账号占用和重复选题入队检查使用 SQLite 事务。其他进程不能解除仍由原进程持有的账号占用。
- 进程拥有随机身份及操作系统自动释放的文件锁；原进程只要仍持锁，旧时间戳不会让另一篇并行执行。进程退出后，排队中和执行中的任务标为中断，保留最后进度和已有结果，永不自动重放。已完成任务继续返回完成结果。
- UI 的任务编号、进度、错误和结果可在重启后通过原 poll API 读取；沿用原任务记录保留窗口。预览结果仍可供继续出图，业务入库结果仍在审稿台。

## 其他模块级状态的处置

| 状态 | 当前持久化事实 | 本次结论 |
| --- | --- | --- |
| 生成 `_gen_jobs`、FIFO、自动化账号 set | 本次写入 `generation.sqlite3` | 已替换进程内权威状态；线程锁仅协调本机回调与多步 UI 更新 |
| 自动化批次 | `automation_config` / `automation_run`，启动时中断未结束批次 | 保留既有执行记录，不恢复提交动作 |
| 笔记学习 | `note_style_import.job_json` 和结果 | 保留既有持久化状态及 runtime identity 判定 |
| 账号对标 | `benchmark_import` 保存草稿和应用结果；即时进度仍在内存 | 可继续读取保存的草稿；进程退出前的即时进度尚未增加独立日志 |
| 单篇/批量发布 | 审稿与归档保存业务结果；任务进度字典仍在内存 | 不改为可恢复执行队列。未来可增加只读状态日志，必须保留“提交后错误不自动重放、成功但归档失败不回待发布”的规则 |
| 选题建议 | 已落库选题持久保存，未确认的建议和即时进度在内存 | 本次未新增草案日志；不得把重启后的草案恢复等同于重新调用收费 AI |
| 扫码 `_qr_jobs` / `_qr_sessions` | 登录结果和 cookie 已持久化；浏览器、取消事件和二维码生命周期属当前进程 | 会话对象不能序列化；重启后重新扫码，未来如保存诊断状态，只保留状态元数据，不复活旧二维码或浏览器 |
| 更新 / 浏览器修复 | 安装事务、运行时维护锁及其专用结果 | 保留各自事务所有权，不能用统一 job 表替代操作系统锁或安装回滚 |

因此，本次没有把所有内存字典机械替换成可恢复队列。新增的耐久执行顺序只覆盖生成；其他模块的即时进度记录缺口仍如表所列。
