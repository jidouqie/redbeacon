# RedBeacon central download integration

- SOP: `/Users/diaojiawang/code/bytestaff-download/docs/multi-project-download-node-sop.md`, version 1.3.
- Project slug: `redbeacon`.
- Publication custody: `central-download-node-window` through the global `bytestaff-digital-employee-publish` Skill.
- Release unit: `app`, kind `application`; it contains the Windows x64 and macOS arm64 clients, all channel installers, one channel skill bundle, Playwright Chromium for both platforms, CloakBrowser Chromium for both platforms, and non-secret build/provenance metadata.
- Build entry: `tools/build_desktop_local.sh --channel test` or the explicitly approved stable equivalent. The project build never receives OSS credentials, uploads bytes, accesses the download node, generates a public manifest, or changes public traffic.
- Clean source: `dist/local-build/test/release-artifacts` for test and `dist/local-build/stable/release-artifacts` for stable. `tools/check_release_artifacts.py` rejects links, hidden paths, unsafe permissions, empty files, missing platform packages, missing runtime archives, incomplete skill bundles, and mismatched build evidence.
- Provenance: `release/release-contract.json` is committed in this repository. Both desktop packages come from one committed CLI archive; installer and build sources come from one committed root archive. `metadata/build-evidence.json` records both commits, source hashes, toolchain versions and the exact platform set.
- Canonical manifests: `https://bytestaff-download-releases.oss-cn-shanghai.aliyuncs.com/projects/redbeacon/test/latest.json` and `https://bytestaff-download-releases.oss-cn-shanghai.aliyuncs.com/projects/redbeacon/stable/latest.json`.
- Canonical artifact mapping: every entry supplies `path`, `size`, `sha256`, immutable central OSS `url`, `node_url`, and ordered `download_urls=[node_url,url]`.
- Node origin binding: the current project receipt and protected publisher profile use `https://download.bytestaff.jiomig.com`; new `node_url` values use the RedBeacon files namespace, selected channel, immutable release version, and declared artifact path. Clients never hardcode this origin and consume only manifest coordinates. Existing release manifests remain immutable and may keep the legacy IP node URL; their OSS `url` fallback is unchanged.
- Client manifest contract: fetch only the fixed HTTPS canonical URL without redirects; require schema 1, project `redbeacon`, the frozen package channel, strict three-part version, safe relative artifact paths, positive size, lowercase SHA-256, and a central OSS URL under the RedBeacon project namespace. A legacy entry containing only `url` remains consumable.
- Node attempt: use at most one node candidate and one GET stream with `Range: bytes=0-`, no redirects, three-second connect timeout, eight-second first response/first-byte timeout and fifteen-second subsequent read timeout. Require HTTP 206, exact `Content-Range`, exact size and exact SHA-256.
- Fallback: any node DNS, TCP, TLS, timeout, HTTP, redirect, interruption, range, size or hash failure removes the node partial file before one immutable central OSS download path is attempted. The installer and frozen client apply the same order.
- Runtime ownership: Playwright and CloakBrowser archives are selected by exact packaged dependency revision and target platform, stored under the current RedBeacon channel, and verified by a real browser launch. User global caches and inherited cache/binary variables are not trusted.
- Install transaction: the new package, matching skill and exact browsers are prepared and verified before the old app is stopped. The SQLite main file plus WAL/SHM are snapshotted; migration is rehearsed on a copy. Final-path desktop and renderer smokes run before commit. Failure restores the old app and old skill without changing the user database.
- Platform acceptance: macOS runs the isolated installer rollback smoke plus frozen GUI, CLI, renderer and browser checks. Windows PowerShell 5.1 parses every script and performs stable/test install, repeat update, rollback, uninstall, database preservation, x64 PE, desktop, renderer and browser checks in the real Windows 11 VM.
- Public release acceptance: before a test canonical switch, a real packaged client must prove normal node download, node failure to OSS fallback, corrupt node content to OSS fallback, and legacy `url`-only manifest compatibility. The evidence schema is `bytestaff-client-acceptance/v1` and contains no secrets.
- Stable gate: stable requires the user's explicit approval plus a committed `COMPLETE_TEST` record for the exact test run. Any code, installer, skill, contract or artifact-tree change invalidates the prior test conclusion.
- Secrets: this repository stores no OSS credential, node publisher key, root SSH credential or protected project profile.
