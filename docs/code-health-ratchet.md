# Code-health 预算棘轮

CLI 的 `tools/check_code_health.py` 同时验证当前源码上限和 Git 基线中的历史预算。预算、目标与重复代码检测阈值必须是可静态读取的字面量，不执行历史 Python 代码。

| 函数 | 原上限 | 当前上限 | 目标 |
| --- | ---: | ---: | ---: |
| `create_app` | 850 | 777 | 320 |
| `_build_parser` | 500 | 498 | 320 |
| `_create_tables` | 400 | 80 | 80（实际已降至 5 行） |

三个模块分别设为当前实际行数：`browser_engine.py` 1411、UI `app.py` 1501、`core/usecases/creation.py` 1498；目标均为 1000 行。其他模块、函数、前端片段和页面模板继续使用原通用上限。

热点文件发生修改且变小时，其预算必须同步降到“当前行数和目标中的较大值”。不能抬高旧预算，不能通过删除更严格的条目退回宽松的默认值，也不能抬高目标。热点被实际删除时才能移除对应条目。已经达到目标的函数可以在该目标上限内维护。

本机直接运行检查时与 `HEAD` 比较。CI 拉取完整提交历史，PR 与目标分支基线比较，普通推送与推送前提交比较；新分支首推与父提交比较。也可显式传 `--base-ref <提交或引用>`。显式基线不可用会失败；没有 Git 历史的源码归档只执行已提交的当前上限检查。

本次验证：11 个棘轮回归测试，包括独立临时 Git 仓库中的实际收紧检查；完整 CLI 套件 **1173 passed, 1 warning**，健康检查通过。
