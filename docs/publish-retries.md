# 发布失败重试与批量继续

按用户 2026-09-09 最新要求，每篇的发布动作失败后自动重试 3 次，加上首次尝试最多执行 4 次。三次重试分别等待 10、20、30 秒，界面显示第几次重试和本次错误。稿件、账号、图片与发布选项保持一致；每次仍重新计算有效发布时间，无效定时按当前规则立即发布。

核心策略位于 `cli/src/redbeacon/core/usecases/publish.py`。UI 单篇、UI 批量、CLI 和自动化调用同一份逻辑。重试不只匹配网络错误关键词，浏览器控件异常和未收到成功回执也进入有上限的重试。审核、素材与登录等发布条件仍须满足；登录失效时提示重新登录，用户取消则停止后续稿件。

重试前通过发布口检查本次尝试有没有迟到的成功页面或提示。找到则直接使用这份成功回执，不再提交；否则安全关闭失败的浏览器会话并重建。只检查真正尝试过提交的页面，不把其他页面或上一篇的成功提示当作当前稿件回执。若旧会话尚未安全结束，不会并行开启另一份提交。

每篇的四次尝试共用同一笔预留：最终成功只结算一次、归档一次，全部失败才取消预留并写入最终原因。已经成功后的计费回执重试、归档异常不进入浏览器重试，避免重复发布。

UI 和 CLI 的批量发布在一篇耗尽重试后继续下一篇。失败稿仍保留“通过”状态和具体错误；批量完成时显示成功、失败和未尝试数量。CLI 多账号发布也会继续后续账号，最后统一返回失败报告及实际成功数量。保存排期仍然不触发发布。

本次也修复了一个已复现的控件问题：填写完发布选项后仅需让标题输入框获得焦点，不再要求鼠标点击被遮挡的标题框。原有话题编辑结束后的失焦操作保留。

验证使用隔离数据库和模拟发布口，覆盖连续失败后成功、首次加三次重试耗尽、迟到成功回执不重复提交、同一预留只结算一次、失败留稿、继续下一篇、跨账号继续、取消和浏览器会话收尾。运行中的源码客户端需要完整重启才能加载这一改动；当前工作不包含安装包发版。
