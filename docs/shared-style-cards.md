# AI封面＋同风格文字卡片

这项能力已接入源码创作流程与原有 skill 真源。选择一套风格后，AI 只负责封面，内页由客户端根据已确认文字在本机排版。内页阶段无需网络、API Key、文字模型或生图模型；文案和 AI 封面的调用仍遵守原有费用与回退策略。

## 在客户端使用

在「方案」中为当前账号新建或编辑一套通用图文方案，选择 **AI封面＋同风格文字卡片**。可选择固定预设或每篇随机、内页自动分页或指定 1–17 张、以及本方案的品牌文字。设置需要保存，只在用户选择该方案后生效，不迁移旧稿或其他账号默认值。

方案页有 15 种本机内页样张；生成页的「预生成」展示本篇冻结的风格、真实文案和最终封面提示词。继续创作后进入同一审稿台。未完成的桌面创作可在生成页的「可以接着完成的草稿」继续或取消，后台使用原 generation_id。

## 设计与来源

- 一篇冻结 `style_id`、版本、颜色 token、字体校验值、模板、页面参数和品牌文字，并绑定账号及 generation_id。重试读取原快照。
- 当前支持 S01–S15 共 15 种共享编号预设。封面提示词与本机布局读取同一注册表，使用同一配色规则；不是任意 AI 图片自动复刻，也不保证 AI 封面与内页像素一致。
- 本机输出为 1080×1440、RGB 不透明 PNG，检查字形覆盖、文字完整性、页序、字框边界与碰撞，并从纯像素重写图片。
- 字体使用未修改的 Noto Sans CJK SC Bold 与 Noto Serif CJK SC Bold，随包保存固定上游提交、SHA-256 和许可证。许可证允许随软件分发；详见 [Noto Sans 许可证](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE) 与 [Noto Serif 许可证](https://github.com/notofonts/noto-cjk/blob/main/Serif/LICENSE)。不依赖用户电脑上的 Mac 或 Windows 字体。
- 真实 AI 封面来源、本地内页渲染器版本与风格快照写入既有来源记录。AI 声明仍使用原有审核/发布选项，图片规范化不宣称能规避 AI 识别。

## 协议与恢复

原 `creation` 工作包新增共享风格快照与本机渲染说明；一次文案可提供结构化 `inner_pages`，也可由软件对 `card_content` 确定性分页。每页包含从 2 连续编号的 `page`、`title`、`text`，以及可选 `layout`（checklist / sequence / comparison / conditions）。

宿主只执行一个 `cover` AI 图片任务，随后通过 `image-import` 交给官方接管。客户端先保存成功封面检查点，再执行 `inner-render`。内页失败会保留文案、封面和风格；重渲可修订 `body`、`card_body` 或 `inner_pages`，不再次请求封面。完整渲染后由原 `commit` 原子入审，重复提交返回同一审核记录。

客户端预生成、单篇/批量生成以及按账号运行的自动化调用同一套耐久创作协议；内页渲染共用同一端口。老文字卡片、AI 封面、组合卡片和带货模式保留。仅在该账号原有策略允许时使用平台图片回退；禁用时继续本机卡片回退，不自动开启平台能力。

若封面调用结果没有保存，系统会停止再次请求，先核实原调用结果，避免重试产生第二次收费。已成功入审的稿件不会被 `inner-render` 偷换图片。

实际图文验收复用了交接中已有的真实 AI 封面，三张内页由软件新实现重新渲染，经过官方协议进入隔离验收库；没有新增模型调用，也没有改动真实 GEO 批次。预览位于本机 `dist/shared-style-preview/preview.html`，原始验收步骤和来源记录位于同目录 `acceptance.json`。

图文已通过本地图片工具实际查看。浏览器工具的 URL 策略拒绝打开本地 HTML，因此没有声称完成 Chrome 或原生客户端的人工界面验收；HTTP 路由、生成协议与 JavaScript 语法已验证，预览 PNG 可直接查看。

当前中文换行使用禁则、动态布局和常见词偏好，不是完整中文语义分词，个别词仍可能跨行；不会把“消除明显孤行”说成排版完美。超长不可拆分英文、字体未覆盖的字符、过密内容或不合格封面会明确报错，不截断文字冒充成功。修改封面本身与只重渲内页是不同操作，当前内页修订入口保持封面和风格冻结。

本轮只做开发、隔离测试、资源打包检查和预览。尚未生成可发布的双平台冻结客户端、执行新版本安装事务 smoke 或发布任何版本；没有升级已安装的正式客户端。分发仍须经过既有测试版构建、Windows/macOS 安装验证、全局发布流程及用户验收。
