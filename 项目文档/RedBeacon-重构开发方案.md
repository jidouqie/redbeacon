# RedBeacon 重构开发方案

> RedBeacon 的架构重构与功能扩展方案（产品参照物）。pre-launch、用户极少 → 可推倒重做、不背历史迁移包袱。
> ⚠️ **计费/登录/AI 的客户端契约真源 = `RedBeacon-平台接入开发规范.md`**；本文只写产品/数据/选题/skill 设计，§5 计费登录已收敛为指针（避免第二真源）。

## 0. 定位与本次要解决的事
- **产品**：RedBeacon = 小红书 AI 运营「数字员工」（CLI + skill + 独立 UI），bytestaff 平台上第一个 metered 员工（靠生图扣点）。远期愿景=数字员工市场。
- 本次重构四件事：① **数据单一真源**（消灭本地 SQLite 与飞书双写的"孤儿/待审虚报"bug）；② **选题能力升级**（一句话标题 → 创作简报 brief）；③ **授权/计费换模型**（弃买断解锁码 → 对接平台 freemium + 算力点）；④ 新增**仿写/抄爆款**。

## 1. 数据归属（本地 vs 飞书）
判断标准：高频被改/列表型/需移动端 touch/"人拍板"环节 → 飞书；敏感凭证/身份/读多写少富文档 → 本地。
```
🔒 本地内核（只装隐私/钥匙/身份，绝不上传）
   平台设备令牌 · 小红书 cookie/浏览器 profile · 机器码 · 代理凭证
   · 用户自己的飞书 app_id/app_secret（每用户自带应用，钥匙只开自己家门、零跨用户风险，故可安全放本地）
☁️ 飞书 = 唯一业务数据中心（每用户自己租户，一号一多维表格）
   账号数据/策略 · 选题表 · 文案审核表 · 归档表 · 数据分析表(预留)
🚫 不设本地缓存：CLI 每次直连飞书（"图片下载本地"是发布素材、非缓存）。
```
⚠️ 铁律：业务数据**单一真源**，飞书只是承载它的面——直接消灭双写漂移。

## 2. 飞书结构
- **层级**：自建应用(app，1 把钥匙) → 多个多维表格(Base，有 app_token) → 多张数据表(Table) → 多个视图(View)。
- ✅ **一个小红书号 = 一个多维表格(Base)**：表类型用「数据表」分、账号用「多维表格」分。理由=账号天然隔离可单独授权 + 躲单表行数上限 + 视图互不干扰。后期加表=往现有 Base 加数据表，不新建 Base。config 每号绑一个 Base 的 `app_token`，下面各表按**约定表名**定位。
- ✅ **每用户绑自己的飞书企业自建应用**（自己租户）：钥匙只碰自己数据、天然无跨用户风险、账号间物理隔离。代价=非技术用户要自己在飞书后台建应用配权限（引导视频解决）。
- ✅ **开通全自动（已跑通）**：作者维护一个**公开权限模板 Base** → 用**用户自己 app** 调 `POST /drive/v1/files/{token}/copy`（回退 `bitable/.../copy`）把模板复制进用户租户 → 加协作者 + 转所有者。源公开可读、副本落调用方租户 → 不撞跨租户禁制(1064510)。✅ **模板已扩成满配四表 Base**（一次 copy 整表带走所有数据表/视图）+ UI 一键建表落地（`create-base`：copy→授权转移→按名补齐幂等→绑号）；失败降级共享原模板。参考 `services/feishu_api.py`/`feishu_schema.py`、`infra/onboarding.py`。

## 3. 四张数据表（核心设计；逐字段规格见 §10 as-built）

### 3.1 选题表 = 灵感 + 选题合一（设计哲学）
- 选题从"一句话标题"升级成"创作简报 brief"：**核心层必填、蓝图层可空（空则继承账号定位）、对标来源层选填（仿写自动填满）**。
- **出生轻、随生命周期变厚**：规划会量产一句话选题（蓝图全空），坐下写时补蓝图，仿写入口天生满配。
- **灵感 = 早期选题**（同一条命的不同成熟度），用「阶段」字段流转（灵感/选题/弃用），靠视图切"灵感库/选题库"两个面板，不拆两张表。
- 字段分四层：**A 核心**（选题/阶段/内容类型/应用域/问题类型）、**B 蓝图**（切入角度/要点提纲/价值点/互动钩子/关键词标签/聚焦人群/配图方向/参考素材，可空、空则继承账号）、**C 对标来源**（来源类型/对标平台/链接/爆款摘要/为什么爆/量级/截图，仿写填）、**D 流转**（优先级/时效/过期日期/备注）。
- **视图**（飞书杀手锏，字段多但不挤）：💡灵感箱(阶段=灵感) / 📋选题盘面(阶段=选题，按应用域分组) / ✍️写作台(优先级=高，显全蓝图) / 🗂️看板(按阶段拖动)。

### 3.2 全生命周期（跨 4 表流转，热/冷分离）
```
[选题表] 💡灵感 ─人拍板→ 📌选题 ──写成文案──▶ [文案审核表] 📝未审 ⇄ ✅通过 ─发布成功─▶ [归档表] 🗄️已发布
              (选题表删行，brief 快照进文案)              ↘ ❌发布失败(留此重试)
```
- **灵感→选题**：只能**人**推（战略层拍板铁律）。
- **选题→文案**：`generate` 写成文案后该选题**从选题表删除**，其 brief（角度/提纲/对标来源）**快照进新建文案记录**，进文案审核表。
- **文案审核表**只三态：未审核/通过/驳回（+发布失败）；CLI 发布只读「通过」。
- **发布成功 → 移入归档表**（数据资产）：归档表 create + 审核表 delete（飞书无原生 move；半路失败靠对账兜底）。
- 防膨胀：活跃两表始终小、历史沉归档。⚠️ 飞书可被用户手改成非法状态，CLI 读须当不可信数据做防御性校验。

### 3.3 录入/编辑分工（重要交互原则）
- **录入是 AI 的活**：爆款链接/规划生成/仿写提取，全部由 AI 写进飞书表。
- **用户在飞书表里只做"改"**：调角度/改优先级/删/拍板转阶段/改稿标通过。飞书表对用户 = 审阅/微调台，不是录入表单。

### 3.4 账号数据表（键值布局）
单条账号档案用**键值布局**（列：配置项｜分组｜值｜说明），26 项按分组：标识 / 定位内核 / 策略 / 文案预设 / 视觉发布（字段清单见 §10.1）。选题表的"继承默认"从这张取值。
- **账号提示词拆两半**（已定）：① **骨架/模板**（怎么拼、固定话术）= 生成引擎逻辑、**留 CLI 代码**；② **账号专属变量**（定位/受众/语气/视觉…）= 业务数据、**唯一真源=飞书账号数据表**。**严禁本地+飞书双写**。
- **定位 skill 做"深度账号梳理"**：账号升到 ~26 字段后，定位环节带用户把整个账号思路理清——但深度在"覆盖"不在"拷问"：**AI 联网+引导先替用户起草每个字段、用户逐块确认/微调**（录入是 AI 的活、用户只改）。定位 skill 直接写飞书账号数据表、写完顺带铺第一批选题。

### 3.5 文案审核表 / 归档表
- **文案审核表**（兼容旧版）：保留旧 6 字段（标题/文案/图片/标签/状态/发布时间），**唯一打破=状态去掉「已发布」**（发布成功移归档）；新增 5 字段（内容类型/应用域/选题快照/配图方式/失败原因）。
- **归档表**（数据资产，冷存）：发布成功移入；含基础字段 + 笔记链接 + **预留复盘指标**（点赞/收藏/评论/涨粉/复盘结论，付费版填，先占坑免迁移）。

## 4. 仿写 / 抄爆款（P2 增长功能）
- 内容引擎第三个输入源（前两个=选题库抽题、单篇共创），本质=对标驱动创作。
- 流程：用户在对话窗发链接/文案 → 提取（按平台路由）→ AI 拆解可迁移的钩子/结构 → 拟成满配 brief 落飞书【灵感库】→ 人拍板转选题 + AI 补蓝图 → 复用 generate 生产。
- 🔴 **红线：仿结构、不抄字**——原文只作结构参考、禁整句复用、必换本账号场景/口吻。RedBeacon 天然占便宜（图自己生成、绕过盗图检测）。
- **提取分档**：A 直接粘文案(极低) / B 小红书图文链接(复用 cloakbrowser，中) / C 抖音/视频号/B站(梗概，中) / D 视频逐字 ASR(重)。🔶 **v1 先做 A+B**。
- **计费**：仿写本身 = `features.mimic` 软解锁；提取/拆解/改写走平台对话接口、重新出的配图走平台生图扣点。

## 5. 计费 / 登录 / AI 路由 → 见平台接入规范
> 客户端逐条契约（device flow / checkin / 生图 / 对话接口 / 错误码 / 令牌存储 / 号数软控 / 赠点）= **`RedBeacon-平台接入开发规范.md`**，本节只留产品级要点、不重复：
- **计费模型**：弃买断解锁码、弃钱包充值 → 对接平台 freemium + 订阅 + **账号级会员共享算力点池**（非货币、不可充值转让、到期作废、要更多走升档）。唯一付费平台能力 = **生图**（按成功张数扣点）；**文案/定位/选题改走平台对话接口扣点**（路 B「走宿主免费」已退役）；号数按档软控（free1/Pro3/Max5）。
- **安全铁律**：客户端永不持上游 key（唯一凭据=设备令牌、device flow 签发可吊销）；`account_id` 服务端从令牌解、客户端不传（防 IDOR）；鉴权/扣点全平台服务端、fail-closed。⚠️ 闭源 CLI 技术上=明文可读，**别用客户端校验守值钱的东西、把闸门搬到服务器**。
- **飞书读写：CLI 直连、不走网关**（每用户自带应用、钥匙只碰自己飞书，零跨用户风险，网关不持飞书凭证）。
- **出图大负载：控制面/数据面分离**——控制面（鉴权/扣点）过网关走 KB 小包；数据面（图字节）走 OSS/CDN 预签名 URL。不必为出图买大带宽中枢。
- **客户端改造清单**：平台 `login`(device flow，与小红书 `xhs-login` 命名去冲突) + config 重构（删 AI key、改"平台登录+飞书+代理"）+ 弃解锁码 + 新增 `doctor` + onboarding 改"免费也需注册+配对+首启轻打卡"。

## 6. 已知风险（仍需正视）
- 🟡 **防御性读取**：飞书能被用户手改成非法状态，CLI 读须当不可信数据校验。
- 🟡 **跨表一致性**：发布时同步更新选题/审核/归档，半路失败靠对账扫孤儿兜底。
- 🟢 出图字节网关多半中转一次（非零字节过网关）；网关挂只停生图（文案/文字卡/飞书不受影响）；COGS 定价须先算清真实成本；额度封顶花费但不封滥用模式（限流+异常检测）。
> 已排除/已解决：飞书 app_secret 跨用户暴露（每用户自带应用）；本地缓存漂移（不设缓存）；离线即死（网络应用设计初衷，换设备续进度）；富 Base 开通（公开模板+copy 已跑通）。

## 7. 实施阶段
- **P0 地基**（安全相关趁 pre-launch 先做、依赖在前）：平台后端（外部依赖）+ 客户端（平台登录/文案生图走平台/config 重构/弃解锁码）+ 每用户自带飞书应用直连 + 出图控制面/数据面分离。
- **P1 UX 深度**：飞书选题+灵感合表（字段/视图/阶段机）+ 选题 brief 升级 + 账号数据表落地。
- **P2 增长**：仿写/抄爆款（v1 提取 A+B）。
- **P3 远期**：数据复盘付费版；数字员工市场（中央身份+权益+计量网关，metered 员工扣点、flat 员工只查授权、谁都不碰上游 key）。

### 10.5 跨表数据流 + 字段继承（开发按此实现）
```
选题表(灵感→选题) ─generate→ 文案审核表(未审)：删选题行；选题/内容类型/应用域/角度/提纲/对标来源 → 快照进文案
文案审核表 ─人审→ 通过/驳回；通过 ─publish→ 成功：归档表 create + 删审核行；失败：状态=发布失败+原因
```
**generate 读账号数据补默认（选题留空时）**：聚焦人群←目标受众；配图方向←视觉风格；关键词标签←账号级关键词；语气/开头/排版/emoji/篇幅/文案指南/违禁词/默认配图方式←账号文案&视觉预设。
