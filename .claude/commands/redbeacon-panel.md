> 🗣️ **对用户全程自然语言**：路由 / 调用别的能力是你**内部**的事，**给用户看的回复里不要出现 `/redbeacon-*`、`redbeacon xxx` 这类命令名 / 斜杠命令**——用人话说你要做什么（如「我来帮你生成一篇」而不是「运行 /redbeacon-generate」；「觉得不对劲随时跟我说」而不是「去 /redbeacon-diagnose」）。**除非用户主动说想用命令 / 想看命令，否则别提、别列命令。** CLI 命令是你在后台执行的，用户无感。

> **【面板 skill】** 纯文字让用户理解整个账号配置太抽象。这个 skill 把**已经聊出来的账号方案**渲染成一个两栏网页：左边是定好的配置（每项都预填好了，用户看哪不对改哪，不用自己从零写），右边能**一键生成一篇预览**看效果。用户弄好点「完成返回对话」，改了哪些会回传给你（AI），你接着聊。
>
> 核心理念：默认用户**不知道**该怎么填，所以页面打开就是满的、能直接用；用户只做"审阅 + 微调"，不做"填空"。

---

## 适用时机

- 用户说「打开面板 / 给我看看现在的配置 / 我想自己看着改 / 生成一篇看看」
- `/redbeacon-locate` 聊完定位后，用面板让用户通览确认 + 试生成
- 你判断纯文字说不清账号全貌时，主动建议：「我开个面板你直接看着改？右边还能直接生成一篇看效果。」

> **单账号 vs 多账号管理台**：上面说的是**单账号**面板 `redbeacon ui account --account-id {ID}`。
> 如果用户是 **Pro 多账号**、想「统一管理 / 在一堆账号间挑一个进去调 / 列出所有账号」——用 **多账号管理台**（见下「Pro 多账号管理台」）。

---

## Pro 多账号管理台（`ui manage`）

```bash
redbeacon ui manage
```

一页把**所有账号列成卡片**（编号·备注·在线态·定位·待审/已发·选题余量），点某张卡的「⚙ 进入配置」就在**新窗口**打开那个账号的内容调试面板（即上面的 `ui account`，调完关掉那个窗口、列表还在）。适合账号多时挨个调。

- **触发**：用户说「多账号管理 / 把所有号列出来 / 我想挨个号调一下 / 在账号之间切换配置」。
- **Pro 门槛**：免费版未解锁会被 CLI 拦下（返回 error + 引导用单账号 `ui account`）。别绕过，按 error 引导用户解锁或用单账号面板。
- 它是一次性本地服务，点「关闭管理台」或超时即退；点开的每个账号面板是各自独立的窗口/服务。

## 第一步：选账号

```bash
redbeacon accounts list
```

0 个 → 先 `/redbeacon-accounts`。1 个 → 自动用，记 `{ID}`。多个 → 让用户指明是哪个账号。

---

## 第二步（重要）：先把对话结论写进库，再开面板

面板会优先显示**库里已有的配置**；库里空的字段才用通用默认兜底。所以**开面板前，先把这次对话里已经聊清楚的东西落库**，这样用户打开看到的是"我们聊出来的方案"，而不是一堆通用默认值。

- 聊到了定位 → 先 `redbeacon strategy patch --account-id {ID} --data '{...}'`
- 聊到了某类内容的写法 → 先 `redbeacon strategy prompt-set --account-id {ID} --type "<类型>"`
- 聊到了配图偏好（含用户发的参考图你抽出的提示词）→ 先 `redbeacon strategy image-set --account-id {ID} --data '{...}'`

> 没聊到的字段不用管——面板会用合理默认填上，绝不会出现空白项。

---

## 第三步：开面板（一次性本地服务，命令期间存活，结束即退）

```bash
redbeacon ui account --account-id {ID}
```

这条命令会：
1. 打开浏览器本地页面（localhost 随机端口），先打印一行 `{"status":"ui_opened","url":...}`。
2. **阻塞等待**——用户可以反复：改左边 → 点「⚡ 生成一篇预览」看右边效果 → 再改 → 再生成。
3. 用户点「完成返回对话」后，命令打印一行结构化 JSON 并**自动退出**（服务不常驻；30 分钟无操作也会自动超时退出）。

告诉用户：
> 已经打开配置面板。左边是按我们聊的内容定好的方案，你看哪不对改哪、不用全填；右边点「生成一篇预览」能直接出一篇看效果。弄好了点「完成返回对话」，再回来跟我说。

> ⚠️ 这条命令会一直挂起直到用户点「完成返回」或超时——这是正常的，耐心等它结束，别中途杀掉。

---

## 第四步：读回用户改了什么，接着对话

命令结束后看最后一行 JSON：

```json
{"finished": true, "timed_out": false, "account_id": 1,
 "changed": {"strategy": ["tone","niche"], "content_types": ["干货科普"], "image": ["mode"]},
 "any_change": true}
```

- **`any_change: true`** → 把 `changed` 用人话念给用户确认一致，例如：
  > 收到，你在面板里调了：账号的「语气」和「赛道方向」、「干货科普」的写法、还有配图方式。这些我都记下了。要不要我再帮你生成一篇，或者还有哪里想调？
- **`any_change: false`**（finished=true 但没改）→ 用户看完觉得没问题：
  > 你看完没动什么，那就按现在这套来。随时想调再叫我。
- **`timed_out: true`** → 用户挂着没点完成就超时了，**不是报错**，照实说：
  > 面板超时关掉了。期间你保存过的改动都已经生效；没保存的没动。要继续可以再开一次。

> 注意：预览生成出来的笔记会进内容队列（不消耗选题库）。用户在面板里生成过几篇，内容队列里就会多几条 `pending_review` 的，正常现象。

## 面板里有什么（都已预填，用户只改不填）

| 区块 | 内容 | 落到哪 |
|---|---|---|
| 这个号是做什么的 | 赛道方向 / 目标读者 / 差异化亮点 / 变现方向 / 读者痛点 | strategy.data |
| 内容怎么写 | 语气 / 开头风格 / 排版风格 / 表情用量 / 篇幅 / 视觉感觉 | strategy.data |
| 各类内容的写法 | 每个内容类型一个框（干货科普/痛点解析/经验分享…） | content_type.prompt_template |
| 配图 | 配图方式 / 卡片配色 / AI 配图模型 / AI 配图提示词 | image_strategy |
| 右栏 | ⚡ 生成一篇预览（用左栏设定，不消耗选题、落库、配图按设定一起出、不推飞书） | content_queue |

> 要用参考图/参考文案抽取风格（多模态），仍在对话里做（`/redbeacon-locate`、`/redbeacon-strategy`、`/redbeacon-diagnose`）——抽出来落库后再开面板，用户就能在面板里看到并微调。面板本身不读图。

---

## 注意

- 面板服务是**一次性**的：命令运行期间临时听一个本地端口供网页回写，命令一结束就 `server_close`，不是常驻 daemon，符合本项目「无常驻服务」原则。
- 命令阻塞期间别并行跑别的同账号小红书命令（浏览器会话可能冲突）。
- 多账号各自独立：面板按 `--account-id` 取数，不会串号。
- 读回 `changed` 后跟用户对齐一次，再决定下一步。
