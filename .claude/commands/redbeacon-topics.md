> 🗣️ **对用户全程自然语言**：路由 / 调用别的能力是你**内部**的事，**给用户看的回复里不要出现 `/redbeacon-*`、`redbeacon xxx` 这类命令名 / 斜杠命令**——用人话说你要做什么（如「我来帮你生成一篇」而不是「运行 /redbeacon-generate」；「觉得不对劲随时跟我说」而不是「去 /redbeacon-diagnose」）。**除非用户主动说想用命令 / 想看命令，否则别提、别列命令。** CLI 命令是你在后台执行的，用户无感。

> **【选题 skill】** 选题是账号的**战略层**，不是生产时被催着挑的耗材。这是一场**你主导、AI 参谋**的规划会：你出想法，AI 联网取真实痛点、按账号定位和「应用域网格」给建议给数据，一起把它规划成一批铺得开的选题，**你拍板入库**。
>
> 什么时候来：定位定完铺第一批 / `/redbeacon-generate` 预警选题快用完 / 你想重铺选题。入库后由 generate 消费，无本地审核。

## 第零步：选账号 + 摆盘面（先给数据，别上来就甩选题）

```bash
redbeacon accounts list                              # 定 {ID}（1个自动用，多个让用户指明）
redbeacon strategy get   --account-id {ID}           # 定位：赛道/受众/痛点/支柱/差异化
redbeacon topics stats   --account-id {ID}           # 数量/分布 + by_domain（应用域覆盖盘面，真实存档）
redbeacon topics list    --account-id {ID} --used 0  # 现有未用题（每条带 application_domain / problem_type）
redbeacon content list   --account-id {ID} --limit 8 # 最近标题 → 查重基线
```

把**选题盘面**摊给用户看，而不是直接出题。**应用域覆盖直接读 `topics stats` 的 `by_domain`（精确存档，不是猜）**：

> 你账号现在的选题盘面：
> - **定位**：{一句话 niche + 差异化}
> - **应用域覆盖**（来自 by_domain）：【{应用域A}】{n}条、【{应用域B}】{m}条……，而【{你按定位该有但 by_domain 里没有的}】还空着；`(未标应用域)` 那批是早期没打标的，可顺手回填
> - **最近发过**：{3-4 个标题}——这些角度先避开

> 核心心法：**定位是判断"底座"，不是每篇都要复述的主题**。底座只有一个，应用域有无数个——这场会就是用一个稳定底座去铺开不同应用域。

## 第一步：先请你出想法（主角是你，优先级最高）

**先邀请用户出料**，再谈 AI 提议——用户的想法是种子：

> 最近想讲点啥？都可以丢给我：
> - 客户/同行问过你的问题
> - 你刷到的对标笔记、热点
> - 你想表达的某个观点 / 不吐不快的点
> - 最近遇到的真实案例

用户可以发一段文字、一篇博主笔记、一个零散念头。**你（AI）读懂它，记成"种子想法"**。用户一时没想法也没关系，跳到第二、三步以 AI 提议为主，但要持续回钩「这个方向你认不认」。

---

## 第二步：联网取真痛点（给数据，别凭空编痛点）

出题前**先联网**找该领域真实的痛点 / 案例 / 对标讨论（用你的网页搜索能力），作为出题依据——不是 AI 脑补痛点：

- 搜：`{niche}` 相关人群真实在抱怨什么、踩什么坑、争什么；结合用户的种子想法定向搜。
- 把找到的真实信号**简述给用户**：「网上这类人真正在痛的是 X、Y，有个案例是 Z」。
- 出题时**标注来源**：哪些贴着联网验证的真实痛点、哪些是你/用户的自有洞察（无网络验证就明说）。

> 这一步对齐用户内容体系里「痛点必联网验证、不臆测」的铁律——选题贴真实需求，才不自嗨。

---

## 第三步：把想法 + 缺口，塑成「应用域 × 问题类型」选题网格（给建议·结合定位）

这是 AI 出力的核心，两件事：

1. **把用户的种子想法落地成成形选题**：每个想法 → 对齐定位改写成可直接创作的选题（一句话、≤25字），标上它落在**哪个应用域 × 哪种问题类型**，附一句"为什么这么定"。**让用户的想法真正变成库里的题**。
2. **补缺口**：用户想法没覆盖到的应用域，AI 按定位补提议，让这批铺得开。

铺成一张**网格**给用户看，标清每条来源：

| 应用域＼问题类型 | 识别 | 盲区 | 决策 | 替代 | 反例 | 后果 |
|---|---|---|---|---|---|---|
| 场景/对象/环节/关系/阶段… | … | … | … | … | … | … |

- **应用域** = 同一个定位能落到的不同**场景 / 对象 / 环节 / 关系 / 阶段**（按账号定位列 5-7 个真实贴合的）。
- **问题类型** = 识别 / 盲区 / 决策 / 替代 / 反例 / 后果（是什么 / 没注意到的 / 怎么选 / 用什么替代 / 反过来的例子 / 会怎样）。
- 每条标 `🌱你的想法` / `🤖AI补` / `🔗联网`，让用户一眼看清这批是怎么来的、铺得匀不匀。

> 自检：网格如果挤成一团（都一个应用域、都论证同一个点）就是换汤不换药，重铺。

---

## 第四步：讨论 → 你拍板 → 入库（入库后剪，少来回）

跟用户来回调到满意：「这个角度太软换掉」「【乙方关系】多来俩」「这条改尖锐点」——AI 就地改网格。

拍板后**连同应用域/问题类型一次性入库**（用 `--json`，把整张网格的元数据一起落库，下次盘面才精确；`content_type` 按 `topics types` 实际为准）：

```bash
redbeacon topics batch --account-id {ID} --json <<'EOF'
[
  {"content":"选题1","content_type":"痛点解析","application_domain":"乙方关系","problem_type":"反例"},
  {"content":"选题2","content_type":"干货科普","application_domain":"行业定价权","problem_type":"决策"}
]
EOF
```

> 返回 `{"inserted":N,"total":M}`（重复的自动跳过）。**务必带上 `application_domain` 和 `problem_type`**——这是这次规划的存档，决定下次开会时盘面准不准。`content_type` 缺省可回退 `--type`。

> **入库后剪，不是入库前逐条挑**：贴定位的题大概率全留，先一次性入库，再请用户报哪条不要，删掉即可——比逐条点选少一个来回：
> ```bash
> redbeacon topics delete --account-id {ID} --ids 12,15
> ```

收尾核对并给小结：

```bash
redbeacon topics stats --account-id {ID}
```

> ✓ 这批铺了 {N} 条，覆盖 {M} 个应用域；其中 {k} 条来自你的想法。够发一阵了，选题快见底我会再喊你开一场。

## 和其他 skill 的衔接

| 场景 | 关系 |
|---|---|
| 刚定位完账号 | 从 `/redbeacon-locate` 过来开第一场规划会 |
| generate 预警选题低 | `/redbeacon-generate` 会把你引到这儿补，而不是生产途中硬塞 |
| 生产中库空了 | generate 会临时按"还没覆盖的应用域"拟一篇、**发你确认**再生成兜底；但正经补还是回这儿开会 |
| 选题跑偏想推倒重来 | 先 `topics delete … --all` 清空，再开一场重铺 |

---

## 注意

- 选题是战略层，**人拍板**；AI 给数据 + 建议 + 定位/应用域框架，不替用户决定方向。
- **先联网验证真痛点再出题**，优先于凭空编。
- 这不是表单是规划对话：先摆盘面、先请用户出料，再谈 AI 提议。
- 无本地审核；选题入库后由 `/redbeacon-generate` 消费。
- 命令失败走 stderr `{"error","next"}`，把 error 给用户看、按 next 自愈。
