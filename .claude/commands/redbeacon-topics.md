> 📦 **数据都在本机**：选题存本地库（`~/.redbeacon`），无需飞书。`topics` 命令读写这一份。（飞书云端源现阶段搁置，不用管。）

> 🤝 **交互风格 = 像得力下属服务老板**：主动带领、别让用户懵；用户没熟之前你来引导，熟了就让他自然语言直说。
> - **全程人话**：给用户的回复不出现 /redbeacon-* 或 redbeacon xxx 这类命令名/斜杠（那是你后台执行的），用「我来帮你生成一篇」这种说法；除非用户主动要命令，否则别提、别列。
> - **给选择必须编号 + 换行排版**，让用户回一个数字就行，例如：
>   ```
>   你想先做哪个？
>   1. 写一篇（我列选题你挑）
>   2. 先审那几篇待审的
>   3. 补一批选题
>   回数字就行，也可以直接跟我说。
>   ```
> - **把输入成本压到最小**：能给选项就别让用户打字，能一个数字就别让他写句子；该替他想的下一步你先想好、给推荐（标「推荐」）。
> - 用户**熟了会直接自然语言**提要求（「写第3条」「发出去」「换个标题」）→ 照做，别硬塞编号流程。

> **【选题 skill · 这是你的主场】** 选题是账号的**战略层**，不是生产时被催着挑的耗材。这是一场**你主导、AI 参谋**的规划会：你出想法（**没想法也行，见下「托管模式」**），AI **联网取当下真实痛点/热点/事件**、按账号定位和「应用域网格」给建议给数据，一起规划成一批铺得开的选题，**用户拍板入库**。
>
> 🔴 **为什么这件事非 skill 不可**：网页操作台能管选题库（增删改、AI 补一批），但**它没有联网检索能力**——「按这个账号定位，去互联网上找此刻正在发生、且和它匹配的真实事件/热点/痛点，再针对性推荐选题」**只有你（Claude Code / Codex，自带联网 + 判断）能做**。这正是「有 AI 助手就把上限用到极高」的头号体现。别把它降级成"随便凑几个选题"——**要联网、要贴当下、要对着定位**。
>
> **选题库 = 单一真源**（本地库）。出题/列表/库存都读写这一份，本地读写恒可用、不会因为网络失败。
>
> **入库后想让用户可视化地翻/勾/管这批选题** → 一句话告诉他"选题都进库了，想一条条翻看或批量整理，我给你把选题页打开"，然后 `redbeacon ui app --page 选题 --account-id {ID}`（把用户送进网页选题页）。规划/发现留在对话（你的强项），逐条管理交给 UI（它的强项）。
>
> 什么时候来：定位定完铺第一批 / `/redbeacon-generate` 预警选题快用完 / 用户想重铺 / **用户说"帮我想想写什么""不知道发啥"**。**入库即可用**（不用人工二次确认转入），由 generate 消费，无本地审核。

## 阶段（选题表「阶段」字段：选题 / 弃用；灵感为历史遗留态）

- **选题**＝可被 generate 取用的库存，**入库默认直接落这一态**（不再有"先收进灵感箱、等人拍板转选题"的二级确认关卡）。**库存量 = 阶段≠「弃用」的行数**（没有"已用/未用"——写成文案就直接删行）。
- **弃用**＝看过否掉、但想留个痕的（软删除，不进列表但没物理删）。
- 「灵感」是改版前的历史阶段值，老数据仍会正常显示在选题列表里、照常可用——新入库的题不会再落这个态，这个词以后不用再跟用户提。

## 第零步：选账号 + 摆盘面（先给数据，别上来就甩选题）

```bash
redbeacon accounts list                                # 定 {ID}（1个自动用，多个让用户指明）
redbeacon strategy get   --account-id {ID}             # 定位：赛道/受众/痛点/支柱/差异化 + 账号级关键词/选题边界
redbeacon topics stats   --account-id {ID}             # 库存(可用条数) + by_domain（应用域覆盖盘面）
redbeacon topics list    --account-id {ID} --stage 选题 # 现有选题（每条带 record_id / 应用域 / 问题类型）→ 别和库里已有的撞
redbeacon content archive --account-id {ID}            # 已发布标题 → 查重基线，这些角度先避开别重复发
```

把**选题库现状**摊给用户看，而不是直接出题。**应用域覆盖直接读 `topics stats` 的 `by_domain`（精确存档，不是猜）**：

> 你账号现在的选题库：
> - **定位**：{一句话 niche + 差异化}
> - **库存**：{stats.unused} 条可写选题
> - **应用域覆盖**（来自 by_domain）：【{应用域A}】{n}条、【{应用域B}】{m}条……，而【{你按定位该有但 by_domain 里没有的}】还空着；`(未标应用域)` 那批是早期没打标的，可顺手回填
> - **最近发过**：{3-4 个标题}——这些角度先避开

> 核心心法：**定位是判断"底座"，不是每篇都要复述的主题**。底座只有一个，应用域有无数个——这场会就是用一个稳定底座去铺开不同应用域。

## 第一步：先分叉——你有想法，还是让我来想？（这是入口关键）

摆完盘面，**先给用户这个编号二选一**（别默认他有想法、也别默认他没有）：

```
这批选题，你想怎么来？
1. 我来帮你想 —— 你不用想，我照你的定位上网找此刻正在聊、正在痛的话题，挑贴你账号的推给你（推荐，最省心）
2. 我有点想法 —— 客户问过的问题 / 你刷到的对标笔记 / 想表达的观点 / 最近的真实案例，丢给我
回数字就行，也可以直接把想法甩给我。
```

- **选 1（托管模式 · 用户最常用）** = 用户不知道写什么、把选题托管给你。**你接管**：读账号定位 → **联网**找当下和这个定位匹配的真实事件/热点/痛点（第二步）→ 塑成针对性选题网格（第三步）→ 过眼入库（第四步）。用户全程只需在你列出的候选里点数字，**不用自己憋想法**。这就是这个 skill 最值钱的地方。
- **选 2（共创模式）** = 用户有料。他发一段文字、一篇博主笔记、一个零散念头 → **你读懂它，记成"种子想法"**，仍走第二步联网验证、第三步塑形，把他的想法真正变成库里的题。
- 两种模式下第二步往后完全一样，只是"种子"来自 AI 发现还是用户提供。选 1 也要在推荐时**持续回钩**「这个方向你认不认」，别闷头灌。

## 第二步：联网取当下真实信号（skill 的核心动作，别凭空编）

出题前**必须先用你的联网检索能力**去找真实依据——**这是托管模式的引擎，也是 UI 永远做不到、只有你能做的那一步**。别 AI 脑补痛点。围绕账号定位（`{niche}`/受众/痛点）定向搜三类信号：

1. **真实痛点**：这类人群此刻在抱怨什么、踩什么坑、争什么（论坛/评论区/问答/对标笔记评论）。
2. **当下热点 / 时效事件**：这个赛道**最近正在发生**的事、新工具/新政策/新争议/季节性节点——**贴当下**的选题天然有流量，别只出常青题。
3. **对标爆款**：同领域近期爆了的笔记在讲什么角度（学结构、换本账号场景，别抄字）。

搜完**把真实信号简述给用户**（让他看见你不是瞎编）：

> 我上网看了下，做 {niche} 的人这阵子最戳的是 X 和 Y；还有个正在热的事 Z（{一句话+大概时间}）——这几个都能落成贴你定位的选题。

- **出题时标注来源**：哪几条贴着联网验证的真实痛点/热点、哪几条是自有洞察（没验证就明说）。
- **贴当下、别炒冷饭**：优先能蹭上近期事件/热点的角度；同时对照第零步的**已发布标题**去重，别重复发过的角度。

> 铁律：**痛点必联网验证、不臆测**——选题贴真实需求 + 当下热度，才不自嗨、才有流量。联网失败/搜不到就如实说「这次没搜到实时信号，我按定位和常识出，你把关」，别假装联网过。

## 第三步：把想法 + 缺口，塑成「应用域 × 问题类型」选题网格（给建议·结合定位）

这是 AI 出力的核心，两件事（**种子 = 第二步联网发现的信号（托管模式）或用户给的想法（共创模式），两者一视同仁**）：

1. **把每颗种子落地成成形选题**：每条联网信号 / 用户想法 → 对齐定位改写成可直接创作的选题（一句话、≤25字），标上它落在**哪个应用域 × 哪种问题类型**，附一句"为什么这么定"。托管模式下让**联网找到的真实热点/痛点**真正变成库里的题；共创模式下让**用户的想法**变成库里的题。
2. **补缺口**：还没覆盖到的应用域，AI 按定位补提议，让这批铺得开。

铺成一张**网格**给用户看，标清每条来源：

| 应用域＼问题类型 | 识别 | 盲区 | 决策 | 替代 | 反例 | 后果 |
|---|---|---|---|---|---|---|
| 场景/对象/环节/关系/阶段… | … | … | … | … | … | … |

- **应用域** = 同一个定位能落到的不同**场景 / 对象 / 环节 / 关系 / 阶段**（按账号定位列 5-7 个真实贴合的）。
- **问题类型** = 识别 / 盲区 / 决策 / 替代 / 反例 / 后果（是什么 / 没注意到的 / 怎么选 / 用什么替代 / 反过来的例子 / 会怎样）。
- 每条标 `🌱你的想法` / `🤖AI补` / `🔗联网`，让用户一眼看清这批是怎么来的、铺得匀不匀。
- **内容类型**取账号定位的「内容支柱」+ 选题表已有单选种子（本地内容类型管理已退役，别再去 `topics types`）。

> **每条填两层——核心归类 + 本条独有的创作简报，别只丢个标题就入库**（你联网+网格已经把角度想清楚了，这些信息丢了 generate 写文案时就补不回来）：
> - **① 核心归类（必填）**：内容类型 / 应用域 / 问题类型 —— 这次规划的存档，决定下次盘面准不准。
> - **② 本条独有的简报（必填，这是「信息不全」的病根）**：**切入角度**（这条从哪个反常识/痛点/视角切）、**要点提纲**（3-5 个要点，分号隔开）—— 这两样**每条都不一样、账号默认里没有可继承的**，留空 = generate 写文案时纯丢信息、写出来会泛。有想清楚的话再加**价值点**（读者能得到啥）/**互动钩子**（怎么引导评论）。
> - **③ 账号级、能继承的（留空即可，别逐条填）**：关键词 ← 账号级关键词　·　聚焦人群 ← 目标受众　·　配图方向 ← 视觉风格。用户主动说了某条要特别处理（"这条聚焦宝妈""这条带上 XX 关键词"）才单独填，否则空着让它按账号默认继承。
>
> 一句话：**②每条必写（无处可继承）、③留空继承（账号默认兜底）**——别把两者都当"蓝图层"一起留空，那正是选题信息不全的原因。

> **避开账号「选题边界·不做」**：strategy get 里的 `topic_boundary` 是这个号明确不做的方向——出题时主动避开，别铺到禁区里去。

> 自检：网格如果挤成一团（都一个应用域、都论证同一个点）就是换汤不换药，重铺。

## 第四步：讨论 → 你拍板（过眼确认）→ 入选题库

跟用户来回调到满意：「这个角度太软换掉」「【乙方关系】多来俩」「这条改尖锐点」——AI 就地改网格。

**过眼确认才入库（硬规则）**：网格先编号列给用户看、用户回数字/「都要」确认后，才一次性写选题库——不静默灌库。

拍板后**连同应用域/问题类型一次性入选题库**（用 `--json`，把整张网格的元数据一起落库）——**入库即可用**，不用再多一步「转选题」：

```bash
redbeacon topics batch --account-id {ID} --json <<'EOF'
[
  {"content":"选题1","content_type":"避坑提醒","application_domain":"乙方关系","problem_type":"反例",
   "angle":"反常识开头：客户越催你越要先对齐验收标准","outline":"验收标准写进合同;每周同步进度截图;留一条改稿边界;超范围就走变更单","value_point":"少扯三次皮","hook":"评论区问你被白嫖过几次"},
  {"content":"选题2","content_type":"工具测评安利","application_domain":"行业定价权","problem_type":"决策",
   "angle":"先戳痛点：报价永远比同行低还是接不到单","outline":"按价值分层报价;给三档套餐锚定;先谈交付物再谈钱"}
]
EOF
```

> 返回 `{"inserted":N,"total":M,"record_ids":[...]}`（重复的选题文本自动跳过）。**每条都带上核心归类 `application_domain`+`problem_type` + 本条独有的 `angle`(切入角度)+`outline`(要点提纲)**——角度/提纲是「信息不全」的病根，每条不一样、无处继承，别省。想清楚了再加 `value_point`(价值点)/`hook`(互动钩子)/`audience`(聚焦人群)/`note`(备注)；`content_type` 缺省可回退 `--type`。这些字段全是自由文本、不是固定选项——按用户聊出来的实际说法填，不用往预设词上凑。（`angle`/`outline`/`value_point`/`hook`/`audience`/`note` 这些字段近期版本起 batch 才支持落库，很旧的版本会静默丢弃——若发现没落库先 `redbeacon update`。）

> **入库后还能剪**：贴定位的大概率全留；用户报哪条不要，按 record_id 删（record_id 来自 `topics list`）：
> ```bash
> redbeacon topics delete --account-id {ID} --ids recXXXX,recYYYY
> ```

收尾核对并给小结：

```bash
redbeacon topics stats --account-id {ID}
```

> ✓ 这批铺了 {N} 条，覆盖 {M} 个应用域；其中 {k} 条贴着我上网找到的当下热点/痛点（或"来自你的想法"）。够发一阵了，选题快见底我会再喊你开一场。

## 另一条路：平台 AI 补题（`topics suggest`，⚡扣点）

上面第二~四步是**你自己联网 + 定位判断**出题、再 `topics batch` 写库——**这是招牌路径，质量最高、贴当下**，能联网就优先走它。

**平台 AI 补题**是**另一条更快但更粗**的路：让平台大模型按账号定位直接吐一批候选（每次约 1 点），不联网、不贴实时热点。**什么时候用它**：
- 你的联网这次不可用 / 用户明说「别费劲搜了，快给我凑一批」；
- 想跟自己联网出的题**交叉对照**、多一批备选让用户挑。

流程（先跟用户说一句「这次让平台直接补一批，会花 ~1 点算力，行吗」，得到同意再跑）：

```bash
redbeacon topics suggest --account-id {ID} --count 10 --idea "偏向职场副业"   # 平台补候选，不入库，返回 items 给人挑
```

把返回的候选编号列给用户过眼、剪掉不要的，确认后写库（`accept` 读 suggest 输出的 items 全字段落库，阶段=选题）：

```bash
redbeacon topics suggest --account-id {ID} --count 10 > /tmp/cand.json   # 先接住候选
# 用户剪定后：
redbeacon topics accept --account-id {ID} --json < /tmp/cand.json
```

**引导语模板（平台补题的"人格设定"，可调）**——平台补题时用的提示词骨架，用户可自定义（也是网页选题页「AI 补题」按钮用的同一份）：

```bash
redbeacon topics suggest-template get --account-id {ID}                 # 看当前引导语（空=系统默认）+ 可插占位符
redbeacon topics suggest-template set --account-id {ID} --text -        # 存自定义（stdin 传，占位符如 {赛道}{补题数量}）
redbeacon topics suggest-template set --account-id {ID} --reset         # 清掉自定义、退回系统默认
redbeacon topics suggest-preview --account-id {ID} --count 10           # 不扣点：拼出这次真会发给平台的完整提示词，供核对
```

> 用户想「让 AI 补题更懂我的号」时，就是改这份引导语。改完先 `suggest-preview` 拼给用户看一眼实际提示词（不扣点），再 `suggest` 真补。

## 改 / 删已有选题（用户说「那条选题改一下 / 删了」）

先列出来让用户按编号指哪条（别让他背 record_id）：

```bash
redbeacon topics list --account-id {ID} --limit 100   # 每条带 record_id / 内容 / 阶段 / 应用域 / 问题类型
```

**改单条**（改文字 / 换归类 / 调阶段 / 调优先级，不用删了重加）：

```bash
redbeacon topics edit --account-id {ID} --id recXXXX --content "改后的选题文本"   # 改文字
redbeacon topics edit --account-id {ID} --id recXXXX --type "痛点解析"           # 改归类
redbeacon topics edit --account-id {ID} --id recXXXX --priority 高               # 调优先级
redbeacon topics edit --account-id {ID} --id recXXXX --stage 弃用                # 软删除、不进列表
```

- 也能改 brief 字段：`--idea`(切入角度) / `--outline`(要点提纲) / `--domain`(应用域)。传空字符串=清空该字段。

**删选题**：

```bash
redbeacon topics delete --account-id {ID} --ids recAAA,recBBB   # 删指定几条
redbeacon topics delete --account-id {ID} --all                # 清空全部（防误删，必须显式 --all）
```

> **🗑️ 删前跟用户确认**（尤其 `--all`）。「不要这几条」= 按编号删指定；「这批全推倒重来」= `--all` 清空再开一场规划会。软删除(`--stage 弃用`)比物理删更稳——留个痕、不进列表，用户反悔还能捞回来，拿不准就用它。

## 和其他 skill 的衔接

| 场景 | 关系 |
|---|---|
| 刚定位完账号 | 从 `/redbeacon-locate` 过来开第一场规划会（locate 第四步已先铺了一批种子选题进本地选题库） |
| generate 预警选题低 | `/redbeacon-generate` 会把你引到这儿补，而不是生产途中硬塞 |
| 生产中库空了 | generate 会临时按"还没覆盖的应用域"拟一篇、**发你确认**再生成兜底；但正经补还是回这儿开会 |
| 选题跑偏想推倒重来 | 先 `topics delete … --all` 清空，再开一场重铺 |

## 注意

- 选题库单一真源（本地库）；库存 = 阶段≠「弃用」的行数，**没有"已用/未用"态**（写成文案=删行）。`reset` / `types*` 已退役（跑了只给短路提示，别用）。
- 选题是战略层，**人拍板**；AI 给数据 + 建议 + 定位/应用域框架，不替用户决定方向；**过眼确认才入库**。
- **先联网验证真痛点再出题**，优先于凭空编。
- 出题填核心层、蓝图留空让其继承账号默认；**避开账号选题边界**。
- 这不是表单是规划对话：先摆盘面、再分叉（帮他想 / 他出料），联网发现 + 定位框架一起塑形，人拍板。
- **托管模式（"帮我想写什么"）是这个 skill 的招牌**：用户零想法也能出一批贴当下、贴定位的选题——靠的是你联网 + 定位判断这两样 UI 给不了的能力，别把它做成随便凑几个。
- 命令失败走 stderr `{"error","next"}`，把 error 给用户看、按 next 自愈。平台补题（`topics suggest`）扣点前先跟用户确认；平台连不上/点数不足会明确报错，如实转达别静默。
