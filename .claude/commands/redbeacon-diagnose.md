> 🤝 **交互风格 = 像得力下属服务老板**：主动带领、别让用户懵；用户没熟之前你来引导，熟了就让他自然语言直说。
> - **全程人话**：给用户的回复不出现 /redbeacon-* 或 redbeacon xxx 这类命令名/斜杠（那是你后台执行的），用「我来帮你生成一篇」这种说法；除非用户主动要命令，否则别提、别列。
> - **给选择必须编号 + 换行排版**，让用户回一个数字就行，例如：
>   ```
>   你想先做哪个？
>   1. 写一篇（我列选题你挑）
>   2. 先审飞书里那几篇
>   3. 补一批选题
>   回数字就行，也可以直接跟我说。
>   ```
> - **把输入成本压到最小**：能给选项就别让用户打字，能一个数字就别让他写句子；该替他想的下一步你先想好、给推荐（标「推荐」）。
> - 用户**熟了会直接自然语言**提要求（「写第3条」「发出去」「换个标题」）→ 照做，别硬塞编号流程。

> **【诊断 skill】** 账号的定位、选题、文案预设、图片预设是一组**联动数据**——最终产出不满意，根因可能在其中任一节点。本 skill 帮使用者从"感觉哪里不对"这条线索，反推到具体出问题的数据，再边聊边调准。
>
> 这不是表单，是诊断对话。先听懂用户"不行在哪"，再动手。

---

## 第一步：选账号 + 拉全账号画像

```bash
redbeacon accounts list
```

确定 `{ID}`（1 个自动用，多个让用户指明）。然后**并行拉全这个账号的运作链路全貌**：

```bash
redbeacon strategy get --account-id {ID}            # 定位（赛道/受众/语气/痛点…）
redbeacon strategy prompt-list --account-id {ID}    # 文案预设（哪些类型用了自定义提示词）
redbeacon strategy image-get --account-id {ID}      # 图片预设（mode/主题/AI提示词）
redbeacon topics stats --account-id {ID}            # 选题库（数量/分布）
redbeacon content list --account-id {ID} --limit 5  # 最近产出几条，定位"不行"的那条
```

> 这一步是给使用者"理清账号是怎么运作的"——先把这条链路（定位→选题→文案预设→图片→产出）摊开给他看，再谈哪里出问题。

如果用户指向某条具体内容，读它的实际产出对照输入：

```bash
redbeacon content get --account-id {ID} --id <内容ID>
```

## 第二步：让用户描述"不行的感觉"

**别急着改。** 用户已经说清了（「太硬」「跑题」）就顺着聊；**说不清的，给个编号菜单帮他定位**，回数字就行：

```
先帮我框一下，主要是哪不对？
1. 文字不对 —— 语气怪 / 开头抓不住 / 结构乱 / 太长太短 / 跑题
2. 配图不对 —— 封面丑 / 太暗 / 字太小 / 想放我本人 / 想换风格
3. 选题方向不对 —— 写的根本不是我想做的内容
4. 都差点意思 / 说不上来 —— 我来帮你逐项看
回数字就行，也可以直接描述哪别扭。
```

顺着用户的选择往下追问，**追问也给编号选项、别开放式连问**。比如他选了「1. 文字不对」，再递一层编号菜单：

```
具体是哪种？回数字（也可以直接描述）：
1. 语气怪 / 太客套 / 不像人说话
2. 开头抓不住、太平
3. 结构乱、分点不清
4. 太长 / 太短 / 啰嗦
5. 跑题、不是我想做的领域
6. 出现了不想要的词 / 品牌 / 引导语
```

其他线索同理顺着推：「不像在对我的人说话」→ 大概率受众设定问题；「方向不是我想做的」→ 赛道或内容支柱问题。

记住用户的原话线索，下一步用它反推。

> **可以让用户直接拿"对的样子"对比**：他要是有喜欢的封面图或喜欢的同类笔记，让他发进来。你读图/读文案，把"他喜欢的"和"当前产出的"做对照，差距往往一眼就能定位到是图片风格、还是文案语气、还是选题方向的问题——比纯靠形容词描述准得多。抽取出的提示词后续可直接落库（`strategy image-set` / `strategy prompt-set`）。

## 第三步：从线索反推问题节点

把"感觉"映射到具体数据节点（一个症状可能牵涉多个节点，按可能性排查）：

| 用户的感觉 | 大概率根因节点 | 去查/改的数据 |
|---|---|---|
| 语气太硬 / 太客套 / 不像人说话 | 定位 | `tone` |
| 开头抓不住、太平 | 定位（+文案预设） | `opening_style`、内容类型的写法指引 |
| 太长 / 太短 / 啰嗦 | 定位 | `content_length`、`format_style` |
| 结构乱、分点不清 | 文案预设（写法指引）+ 定位 | 该内容类型的写法指引、`format_style` |
| 跑题 / 不是我想做的领域 | 定位 或 选题 | `niche`、`content_pillars`；或选题本身 |
| 几篇产出都在说同一件事 / 换汤不换药 / 看着都差不多 | 选题（应用域撞车）+ 文案预设（把定位当主题） | 最近几篇的切入面分布、`content_pillars`；预设有没有写成"每篇都要讲 XX" |
| 不戳人、没共鸣 | 定位 | `pain_points`、`target_audience` |
| 像在对错的人说话 | 定位 | `target_audience` |
| 出现了不该出现的词/品牌/引导语 | 定位 | `forbidden_words` |
| 选题本身就没人想看 | 选题（+痛点） | 选题库内容、`pain_points` |
| 图风格不对 / 太丑 / 不搭 | 图片预设 | `mode`、`card_theme`、AI图 `prompt_template` |

**先把你的判断讲给用户听，再给编号选项让他确认或纠正**（别开放式问"要不要这么调"）：

> 我看了你的定位，`tone` 现在写的是『亲切自然』，但你说文案太客套——问题大概率在这。回个数字：
> 1. 对，就把语气调得更直给（**推荐**）
> 2. 不是这个问题 —— 说说你实际的感受

让用户确认或纠正，再动手。改错了节点等于白改，所以**先对齐判断**。

### 专项：同质化 / 换汤不换药（最隐蔽、最值得单独排查）

"每篇看着都差不多、像在反复讲同一件事"是高频且不易自察的病。先把最近几篇摊开找证据：

```bash
redbeacon content list --account-id {ID} --limit 8   # 看一串标题
redbeacon topics list --account-id {ID} --used 0     # 看未用选题是不是也都一个角度
```

把这些标题/开头并排看，问自己一句：**它们是在从不同侧面打同一个定位，还是把同一个观点换着说法讲了好几遍？** 后者就是同质化。根因通常是这两个，对症下药：

1. **选题应用域撞车**——选题全挤在同一个切入面（同一类场景/对象/环节/问题类型）。
   - 修：重做一批选题，**刻意铺开不同应用域**（换场景、换对象、换关系、换环节）×**不同问题类型**（识别 / 盲区 / 决策 / 替代 / 反例 / 后果），让每篇长出自己的观点和方法，而不是同一个结论讲三遍。带用户去 `/redbeacon-locate` 重铺选题（它的选题生成已内置"应用域自检"）。
2. **把定位当主题**——文案预设里把账号的核心定位写成了"每篇都必须正面复述 XX"。
   - 关键区分：**定位是判断"底座"——用来判断一个选题对不对路的标准，不是每篇都要复述的主题**。底座当主题反复念，就成了换汤不换药。
   - 修：`strategy prompt-set` 把预设改成"紧扣定位去看待这个**具体选题**"，而不是"每篇都要讲定位本身"。

> 一句话给用户：**底座只有一个、应用域有无数个**。好账号是用一个稳定的底座去打不同的应用域，不是把底座本身讲一百遍。

## 第四步：对话式调准（动手改）

确认节点后，调用对应能力改。每改一处都说清"改了什么、为什么、预期效果"：

- **定位字段** → `redbeacon strategy patch --account-id {ID} --data '{"字段":"新值"}'`（只传要改的）
- **文案预设** → `redbeacon strategy prompt-set --account-id {ID} --type "<类型>"`（stdin 喂一句人话写法指引，别写 JSON/占位符，程序会自动拼）
- **图片预设** → `redbeacon strategy image-set --account-id {ID} --data '{...}'`。AI 封面是「**大字报**」（标题大字直接画进图）：用户说封面哪不对（「太暗」「字太小」「想要性冷淡风」「想放我本人」），你把视觉风格写成**结构化封面提示词**存进 `prompt_template`（**带 `{标题}` 占位符 + 竖版3:4**，写法见 `/redbeacon-strategy` C 段）；想**放真人**就让用户发照片、`strategy image-ref-add` 存为参考图走图生图；换配色改 `card_theme`，换配图方式改 `mode`（cards/both/ai）
- **选题** → 删旧补新：`redbeacon topics reset`（标记可重用）或重新 `redbeacon topics batch`/`topics add`；选题方向不对时连带回查 `pain_points`

> 复杂改动可直接引导到 `/redbeacon-strategy`（它有每类的完整操作），诊断负责"定位问题 + 给方向"，策略负责"执行修改"。两者配合。

## 第五步：验证闭环（关键：用「同一个选题」重生，才看得出是参数改对了）

改完别空口说"应该好了"。让用户重新生成一篇对比——**但必须用刚才那篇不满意的同一个选题重生**，否则换了选题，你分不清是"参数改对了"还是"碰巧抽到个好题"。

先把那篇不满意的内容的**原选题**取出来：

```bash
redbeacon content get --account-id {ID} --id <刚才那条内容ID>   # 看它的 topic 字段
```

拿 `topic` 原文用 `--topic` 同题重生（`--topic` 绕过选题库、不消耗库存，正好做 A/B）：

```bash
redbeacon generate --account-id {ID} --topic "<上一步取到的 topic 原文>"
```

> 我把 [节点] 的 [字段] 从「旧」改成「新」了。**用同一个选题「{topic}」又生成了一篇**，你对比下前后这两篇——同题同条件，差别就是这次改动带来的。还不对味我们继续往别的节点查。

**说清楚两件容易混的事**（对齐用户预期）：
> 1. 这次改的是**今后这类内容的"预设"**，不是回头修好你正看着的那一篇——那篇要改去飞书手改，或就用这次重生的新版替代。
> 2. 想就单篇做"一次性小调整"（比如就这篇结尾加个钩子），目前去飞书手改最快；改预设会影响之后每一篇。

诊断是迭代的：一轮不准就回第三步换节点、同题再重生，直到产出让用户满意。

---

## 注意

- **先诊断后动手**，节点没对齐前不要改数据。
- 一次只改一个节点再验证，否则分不清是哪处改动起的作用。
- 本地无审核环节，改稿不在这里；这里只调"生产参数"，让下一次生成更准。
- 命令失败走 stderr `{"error","next"}`，照实告诉用户。
