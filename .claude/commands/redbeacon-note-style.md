> **运行前自检**：先执行 `redbeacon --version`。如果命令不存在，必须从当前通道中央 manifest 精确读取安装器并执行；不得猜 zip 名、版本目录或下载地址。

> **【单篇笔记学习】** 当用户贴出一篇小红书图文笔记，并表达“照这篇做”“仿写这篇”“做成这种笔记”“学习这个封面”“把这篇沉淀成方案”等意图时，直接进入本能力。RedBeacon 会读取这篇笔记的标题、正文和封面，用当前账号自己的定位约束文案迁移，并以用户指定的这一张封面为主要视觉依据，提炼成一套可复用方案。分析只生成预览；用户明确确认后才加入方案库。

## 先区分主页与单篇笔记

- `/user/profile/...` 主页、手机端“查看 Ta 的主页”分享文字，且用户要“对标这个账号 / 复刻这个账号” → 去 `/redbeacon-benchmark`。
- `/explore/...`、`/discovery/item/...`、具体笔记分享文字，且用户要“照这篇做 / 仿写这篇” → 留在本能力。
- `xhslink.cn` / `xhslink.com` 短链可直接传给软件，由浏览器核验最终落点。不得根据短链外观猜测页面类型。
- 用户只贴链接、没有说明是模仿账号还是模仿单篇时，只问一个问题：“你想学习整个账号，还是只学习这篇笔记？”

## 不可突破的边界

- 只迁移表达方法和画面结构，不复制原笔记的标题、正文、品牌、人物、价格、案例、联系方式或其他第三方事实。
- 单篇学习与账号对标的视觉目标不同：这里以用户指定的这一张封面为主。纯文字封面继续保持纯文字媒介；摄影、拼贴、多元素、分区结构必须逐项抽象保留，不能擅自改成另一种“更好看”的模板。
- 文案方法要适配当前账号定位；不得把来源笔记的行业事实硬套进当前账号。
- 方案占位符只能使用 RedBeacon 注册表中的合法占位符。
- `analyze` 只给预览，用户没有明确确认时绝不执行 `apply`。
- 新方案默认不替换当前默认方案；只有用户明确选择“设为默认”时才允许追加 `--make-default`。

## 第一步：确定当前账号

先执行：

```bash
redbeacon accounts list
```

- 只有一个账号就直接使用。
- 多个账号且用户没有说清时，一次只问他要把方案加入哪个账号。

## 第二步：学习并展示预览

```bash
redbeacon note-style analyze --account-id {ID} --url "{用户提供的笔记链接或完整分享文字}"
```

命令可能需要一段时间。将返回结果整理成人话，只展示：

1. 这套方案适合解决什么内容任务；
2. 文案的标题句式、正文推进节奏、信息组织和收尾方式；
3. 封面类型、构图比例、元素映射、文字系统、配色材质，以及哪些结构固定、哪些内容可替换；
4. 已隔离的第三方事实数量。

不要把长提示词全文、内部 job 字段、原笔记正文或命令名直接甩给用户。然后只问一次：

> 这套方法可以加入当前账号的方案库吗？
>
> 1. 加入方案库，不改变当前默认方案（推荐）
> 2. 加入并设为以后默认方案
> 3. 暂不保存

用户没有明确选择 1 或 2 时，到此停止。

## 第三步：按确认结果保存

- 选择 1：

```bash
redbeacon note-style apply --account-id {ID} --job-id {JOB_ID}
```

- 选择 2：

```bash
redbeacon note-style apply --account-id {ID} --job-id {JOB_ID} --make-default
```

保存成功后非阻塞打开方案页，让用户亲眼核查：

```bash
redbeacon ui app --detach --page 方案 --account-id {ID}
```

告诉用户：已经把这一篇的文案节奏和封面结构沉淀为可复用方案；原笔记的事实和原图没有进入方案库。

## 失败处理

- 链接实际落到账号主页 → 不要反复重试本能力；按用户意图转到账号对标。
- 标题、正文或封面没有读取完整 → 提醒用户刷新笔记或重新复制分享链接后重试。
- 小红书登录失效 → 引导重新扫码，登录完成后继续同一个用户目标。
- 平台分析失败 → 如实说明并允许重试；不得把普通截图反推结果冒充成 RedBeacon 单篇学习结果。
- 需要肉眼对比长模板时，用 `ui app --detach --page 方案` 把客户端置前，不能让用户在对话里核对一大坨提示词。
